형식 규칙은 `docs/guide/_BRIEF.md` 그대로 (먼저 읽는다). 이번 일은 아래 네 가지다. 분량이 늘어나는 건 괜찮다. 품질이 우선.

## 1. 사실 검수 (가장 중요)
- 장 안의 기술 주장 하나하나(필드 이름, 기본값, 동작 순서, 상태 이름, 알고리즘, 버전별 차이, 명령어 옵션)를 **공식 문서**와 대조한다. WebFetch/WebSearch 를 적극적으로 쓴다. 공식 문서 = 프로젝트 자체 문서 사이트, 공식 GitHub 레포의 docs/소스, kubernetes.io. 블로그는 보조로만.
- 버전은 PoC 가 고정한 버전 기준 (레포에서 확인: Argo CD 차트 10.10.5 = v3.5.x, argo-rollouts 차트 2.43.8, prometheus 차트 29.37.0, Knative v1.23 계열, Cilium 1.20.3, kindest/node v1.37.0, gVisor 20261012.0, kaniko executor v1.23.2, k3s 등. 장에 적힌 버전이 레포와 다르면 레포를 따른다). 해당 버전 문서가 없으면 latest 문서를 보고 차이 가능성을 적는다.
- 틀린 것은 고친다. 레포 코드와 장의 설명이 다르면 레포가 사실이다 (레포 코드는 고치지 않는다. 보고만).
- 【확인 필요】 표시: 공식 문서·소스로 결론이 나면 고치고 표시를 지운다. 끝까지 결론이 안 나면 남기되 "무엇을 어디서 봐야 확정되는지" 한 줄 붙인다.
- `callout fact` 의 공식 문서 링크가 실제로 열리고 그 내용을 말하는지 확인한다. 깨진 링크는 고친다.

## 2. 빠진 핵심 개념 채우기
- 그 기술의 공식 문서가 "핵심 개념(Concepts)" 으로 다루는데 장에 없거나 얕은 것을 찾아 채운다. 3단계 원칙(개괄 → 동작 원리 → 세부 로직)을 지킨다. 우리 PoC 가 안 쓰는 개념이면 "PoC 에서는 안 씀, 본선에서 이럴 때 쓴다" 로.
- 설명이 비약하는 곳(앞에서 정의 안 한 말을 쓰는 곳, "왜" 가 빠진 곳)에 설명을 더한다.
- 새 그림을 더해도 좋다 (그림 번호는 장 안에서 다시 순서대로 매긴다).

## 3. 위에서 아래로 읽히는 흐름
- 처음부터 끝까지 순서대로 읽었을 때, 어떤 용어도 정의되기 전에 쓰이지 않게 한다. 필요하면 절 순서를 바꾸거나, 앞에 짧은 정의를 넣거나, "자세한 건 N절" 로 미리 알린다.
- 절과 절 사이에 이어 주는 문장(앞 절에서 무엇을 알았고, 이 절은 왜 필요한가)을 넣는다.
- `이 장의 지도` 의 절 목록을 바뀐 순서와 맞춘다. h2 id 는 가능하면 유지 (다른 장이 링크할 수 있음). 바꾸면 보고에 적는다.
- 다른 장에서 자세히 다루는 개념은 짧게 요약하고 `<a href="chNN-xxx.html#id">` 로 넘긴다 (중복 설명을 길게 하지 않는다).

## 3-1. 책처럼 읽히게 (Jeong 추가 요청, 2026-10-20 22:05 KST+9)
Jeong 원문: "내가 그냥 책 읽듯이 읽으면 다 읽었을 때 모든 걸 알 수 있어야 한다. 모르는 단어도 따로 마지막에 띡 정리하는 게 아니라, 그런 게 있을 것 같으면 바로바로 설명해서 읽는 플로우에 방해가 되어서는 안 된다. 큰 볼륨의 책을 하나 편찬한다고 생각."
- 독자 기준: Java/Spring 백엔드 개발자, 인프라 실습 경험 적음. 컨테이너·Pod·Deployment·Service·kubelet·etcd·CNI·syscall·커널 같은 기초 용어도 **그 장에서 처음 나오는 자리에서** 한두 문장으로 바로 설명한다. "00장 용어집 참고", "N장에서 설명" 으로 미루지 않는다. 다른 장에 깊은 설명이 있으면 **먼저 한 줄 설명을 그 자리에 쓰고** 그 뒤에 링크를 둔다.
- 약어·영어 용어는 처음 쓸 때 풀어 쓴다 (예: "KPA(Knative Pod Autoscaler, Knative 가 파드 수를 정하는 구성 요소)").
- 읽는 흐름을 끊지 않는다: 긴 용어 설명이 필요하면 본문에 자연스럽게 녹이거나, 바로 아래 짧은 `callout` 한 개로. 각주나 장 끝으로 보내지 않는다.
- 각 장은 그 장만 처음부터 끝까지 읽어도 그 장의 모든 내용이 이해되어야 한다 (앞 장을 안 읽었어도). 단, 같은 설명을 통째로 반복하지는 말고 "한 줄 요약 + 링크".
- 검사 방법: 장을 위에서 아래로 훑으며, 정의 없이 처음 등장하는 용어를 모두 찾아 그 자리에서 설명을 넣는다. 마지막 보고에 "그 자리에서 설명을 추가한 용어 개수"를 적는다.
