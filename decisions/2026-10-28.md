### 준비 범위 (10/28~10/30)

- 선택: ① 도구 통일(Brewfile) ② kind 30분 드릴(kind + Argo CD + kube-prometheus-stack + podinfo + 알림 1개) 3회 ③ k3s 를 multipass VM 2대로 한 번 손으로 + k3d 15분 ④ 골든 시그널·SLO·알림 실습 ⑤ 스택별 "왜" 1페이지 읽고 말하기 ⑥ EKS 는 읽기만.
- 대안: (a) `poc/run-all.sh` 전체 실행을 1순위로 (b) EKS 를 미리 한 번 만들어 보기 (c) 새 PoC(예: OCM 멀티 클러스터) 추가 (d) 문서만 읽기.
- 이유: `labs/06`·`labs/07`·`poc/01~07` 의 `results/` 가 비어 있다 【사실, 10/28 레포】. 주제 무관하게 1일차에 반드시 필요한 건 "클러스터·GitOps·모니터링을 빠르게 세우는 손" 과 "대안을 말하는 입" 이고, 새 PoC 는 주제가 나오면 방향이 바뀐다. EKS 는 비용·시간·프로젝트 금지 규칙. `run-all.sh` 는 2시간·10GB 라 P2.
- 측정값: 없음(드릴 3회 시간, k3s 부팅 시간, 알림 FIRING 까지 초를 `starter-pack/infra-prep/results/drill.md` 에 남기기로).
- 연결 심사 항목: 완성도·데모 30(셋업 속도), 클라우드 활용 30(k3s/EKS 선택 근거), 팀 개발 20(대안 문서).

### 드릴 관측 스택 = kube-prometheus-stack (Operator 포함)

- 선택: `prometheus-community/kube-prometheus-stack` 92.14.1, Alertmanager 끔, ServiceMonitor/PrometheusRule 은 Argo CD 로.
- 대안: `poc/02` 방식(prometheus 단독 차트 + 정적 scrape 설정 + Grafana 따로) / Grafana Cloud 무료 티어 / CloudWatch.
- 이유: 앱마다 `ServiceMonitor`, 알림을 `PrometheusRule` 로 Git 에 두려면 Operator 가 필요하다. "알림 규칙도 GitOps" 를 1일차 기본안으로 내기 위해.
- 측정값: 없음(드릴 3/5 단계 시간과 `monitoring` 네임스페이스 메모리를 재기로. 【추정】 +600MB, +2~5분).
- 연결 심사 항목: 클라우드 활용 30, 완성도 30.

### 알림 1개 = 에러율 5% / for 1m (번 레이트 5)

- 선택: SLI 성공률(비 5xx 비율, 2분 창) 기록 규칙 → `PodinfoHighErrorRate: < 0.95 for 1m`. SLO 99%/30일.
- 대안: 문턱 1%(SLO 그대로) / 다중 창 번 레이트(SRE workbook) / 지연 p95 알림 먼저.
- 이유: 1% 는 잡음, 다중 창은 설명 비용. 데모에서 "일부러 500 → 2~3분 안에 FIRING → 멈추면 해제" 가 한 규칙으로 보여야 한다.
- 측정값: 없음(FIRING 까지 초를 재기로).
- 연결 심사 항목: 완성도·데모 30.

### k3s 연습 = multipass VM 2대 (AWS 아님)

- 선택: `multipass launch` 2대 → server `curl | sh`, agent `K3S_URL`+`K3S_TOKEN`. 스크립트 `scripts/k3s-multipass.sh`.
- 대안: k3d 만 / `poc/07` Terraform 을 AWS 에 apply / kubeadm 으로.
- 이유: "토큰으로 join", "server 를 꺼도 파드는 산다", "노드 삭제 → 5분 뒤 축출" 은 진짜 노드여야 보인다. AWS 는 승인·비용·당일 destroy 가 붙고, 지금 익힐 건 명령 자체. `poc/07` 의 user_data 와 같은 명령이라 그대로 이어진다.
