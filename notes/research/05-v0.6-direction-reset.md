## 0. 결론 먼저

방향을 **갈아엎을 필요는 없고, 비율을 바꾸면 된다.** 1주차 실습 7개 중 5개를 10/6 하루에 끝내서 일정에 약 4~5일 여유가 생겼다 【사실: STATUS.md, 커밋 48e46bc까지】. 이 여유를 인프라 실습 추가가 아니라 아래 네 가지에 쓴다.

| 바뀌는 것 | v0.5 | v0.6 제안 |
|---|---|---|
| 하루 12시간 배분 | 실습 8h + 측정·ADR 2h + 일본어 1h + 정리 1h | 실습 6h + 측정 1h + **조사·주제·설계 문서 3h** + **데모 화면 1h** (10/12부터, 그 전엔 실습) + 협업·면접 준비 0.5h + 정리 0.5h |

## 2. 바꾸는 내용

### 2.1 주제 구체화 (07 결과 반영)

- **주제 후보 확정 【추정, →07 4절】:**
  - **A. 미니 Infrinia**: 모델을 고르면 OpenAI 호환 API가 나오는 멀티테넌트 추론 서버리스 플랫폼 (0↔N 스케일, 테넌트 격리, 토큰 과금). 소프트뱅크 GPU 클라우드 KaaS·Inf-aaS(10월 출시)의 축소판. 가능성 가장 높음.
  - **B. 미니 DSF**: 점수 기반 멀티 클러스터 배치 + 자동 페일오버. 10/18 게이트와 같고, 예선과 이어진다.
  - C(자율 운영 에이전트)와 D(소버린 라우터)는 단독 주제가 아니라 **A 위에 얹는 기능**으로 준비한다 (C = AI 활용 10점, D = A의 라우팅 정책).
- 10/7 오후 R1 슬롯은 필요 없어졌다. 그 2h는 설계 문서 템플릿 작업으로 돌린다.
- **P1 실습 순서 (07 7절):** ① 멀티테넌시(Namespace·ResourceQuota·NetworkPolicy·RBAC, 노이지 네이버 실험) ② CPU LLM 서빙(llama.cpp OpenAI 호환) + KEDA 0↔N, 콜드 스타트 측정 ③ OCM 멀티 클러스터 + 점수 배치 + 페일오버 ④ Lab 06 위 관측 + 자동 조치 에이전트(읽기·쓰기 도구 분리). 상태 이식성(P1-4)은 설계 문서 한 섹션 + 최소 실습, SpinKube·Crossplane 비교는 개념 정리로 내린다.
- 매 실습 README 끝에 **"소프트뱅크 연결" 한 문단**을 붙인다 (→07 7절).
- **"홍석님께 추가 질문" 결과**는 2.3·2.4에 반영한다 (본선 팀 구성 방식, 트랙 구분, 현장 면접 형식).

### 2.2 설계 문서와 데모 화면

- **설계 문서 템플릿 (Claude가 10/8까지 작성, `docs/design-doc-template.md`):** 배경·문제 / 목표·비목표 / 사용자 시나리오 / 아키텍처 그림 / 핵심 결정 표(선택·대안·버린 이유·측정값) / 데모 시나리오 5분 / 측정 계획과 결과 / 리스크·한계 / 다음 단계. 중간 점검 3분과 최종 5분을 이 문서 순서 그대로 읽어 내려가면 되게 만든다.
