## 0. 결론 먼저

1. **주제 예측 갱신**: A(멀티테넌트 추론 서버리스)가 여전히 1순위. 10/6 이후 뉴스로 **D(소버린 라우팅)가 가장 많이 올랐다.** 따라서 연습 주제는 **"A + D 합본"**: OpenAI 호환 추론 게이트웨이 + 테넌트 격리 + 민감도 기반 국내/외부 모델 라우팅. B(멀티 클러스터 점수 배치)는 그 확장으로, C(운영 에이전트)는 "AI가 제안하고 사람이 승인" 기능으로 붙인다. 【추정, 1절】
2. **경쟁 수준이 생각보다 높다.** 부산 회차 최우수 팀은 3개 환경(k3s·EKS·GKE) 동시 배포, Argo Rollouts 카나리 + Prometheus 에러율 자동 롤백, 배포 시간 6분 17초 → 1분 47초 실측을 들고 있다. 작년 본선 최우수 팀 멤버도 올해 예선에 다시 나왔다. "실측 숫자 + 트레이드오프"는 **차별점이 아니라 기본기**다. 【사실, 2절】
3. **심사위원이 실제로 칭찬한 것**(작년 본선 최우수 팀에 대한 공개 심사평): 문제 정의가 명확함, 팀 안의 반대 의견과 PoC로 결정함, 보안·비용·가용성을 같이 고려함, 어려운 기술을 "실제로 동작하는 수준"까지. 【사실, 3절】

5. **공부 계획 변경 요약** (자세한 건 4절)
   - **유지**: K8s 기초, 관측(Prometheus), Terraform, 설계 문서 템플릿, 데모 화면, 결정마다 대안+숫자.
   - **올림**: Argo CD + Argo Rollouts 자동 롤백 (이제 기본기 + Jeong이 맡을 "인프라 한 조각" 1순위), Spring Boot 추론 게이트웨이 (Jeong 강점 + A·D 핵심), "사회 문제" 한 줄 서사.

### 3.3 그래서 가산점·감점 포인트 【추정, 위 사실들의 종합】

가산점 5개
1. 사회 문제 하나 + 구체 사용자 하나에서 모든 인프라 선택이 이어짐 (공식 테마 "클라우드로 사회 문제 해결" 【사실: 모집 공고】, 일본 소프트뱅크 해커톤 심사평 "타깃 설정부터 AI 구현까지 일관성" 【사실】 https://www.softbank.jp/sbnews/entry/20251024_01)
2. "왜 X이고 Y가 아닌가" 표 + 숫자 (지연·비용·복구 시간)
3. IaC + GitOps + 관측 위에서 **라이브로 장애나 스케일을 보여 줌**
4. AI에 가드레일: 최소 권한, 사람 승인, 결정적 코드와 분리 (회사 자체 설계와 같음)
5. 비용·사용률·격리·데이터 위치(소버린) 의식

감점 5개
1. 욕심낸 범위(멀티 클러스터·GPU)가 라이브 데모에서 터짐
2. 클라우드 서비스를 이유 없이 나열
3. 지표·복구 이야기 없음
4. 느리거나 상관없는 AI를 덧붙임
5. 비밀값 Git 커밋, 콘솔 수작업, 한 사람만 배포 가능, 데모 실패 대비 없음
