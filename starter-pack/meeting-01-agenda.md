# 1차 회의 안건 (10/30 금 21:00~22:00, 킥오프 직후 슬랙 허들)

## 0. 전제

- 운영 킥오프(20:00~21:00)에서 팀 빌딩과 주제 공개가 끝난 상태 【사실: 운영 메일】. 그 직후 팀만 남아 1시간.
- 목표: 아이스브레이킹은 10분으로 끝내고, **"내일 오후에 무엇을 들고 올지"와 "누가 어디를 보는지"**를 정해서 나온다.
- 이 회의에서 **정하지 않는 것**: 아키텍처, 기술 스택, 기능 명세, API 명세. 전부 2차(10/31)·3차(11/1)로 넘긴다. 이유는 아래 3절.
- 회의는 허들 녹음 → AI 회의록. 회의록 정리와 노션 반영은 Jeong이 맡겠다고 **먼저 말한다** (리드를 주장하지 않고 리드가 하는 일을 먼저 가져가는 방법).

## 3. 1차 vs 2차 vs 3차: 어디까지 어디서

| 항목 | 1차 10/30 밤 | 2차 10/31 오후 | 3차 11/1 오후 |
|---|---|---|---|
| 사람·시간·일정 | **확정** | | |
| 주제 해석 | 1차 해석, 질문 목록 | **확정**(운영 답 반영) | |
| 데모 장면 | 후보 수집 | **확정 1개** | 대본 뼈대 |
| 아키텍처 | 과제 배정 | **확정** + 버린 대안 표 | |
| 역할 | 임시 | **확정** + 백업 | |
| must / extra | | **확정** | 조정 |
| 기능 명세·API 명세 | | 뼈대 | **확정** |
| 레포·브랜치·이슈 | | 스타터 팩 적용 | 이슈 전부 등록 |

왜 1차에서 아키텍처를 안 정하나: 주제를 처음 본 지 1시간 안에 나온 구조는 다음 날 뒤집히기 쉽고, 뒤집히면 "결정 → 번복" 기록만 남는다. 하룻밤 두고 전원이 초안을 들고 오면 **비교표가 그대로 설계 문서의 "대안과 트레이드오프" 절**이 된다(팀 개발 20점 항목 【사실: 예선 심사 기준】). Jeong 입장에서도 초안을 준비해 갈 수 있다.

## 4. 역할 분배 워크시트

### 4.1 역량 × 시간 표 (자기소개 직후 Jeong이 채움, 본인 확인)

| 이름 | FE | BE/API | k8s | AWS | CI/CD·GitOps | 관측·장애 | AI/LLM | 발표·문서 | 본선까지 총 투입(h) | 맡고 싶은 것 |
|---|---|---|---|---|---|---|---|---|---|---|
| Jeong | 2 | 3 | 2 | 2 | 2 | 2 | 2 | 3 | 70+ | 설계 문서·일정·API, 인프라 한 조각 |
| | | | | | | | | | | |

점수: 3 = 혼자 끝까지 할 수 있음, 2 = 해 봤음, 1 = 배우면서, 공란 = 안 함. 자기 신고라 과장될 수 있으니 2차 회의에서 "그걸로 뭘 만들어 봤는지" 한 줄씩 확인.

- 규칙: 슬롯마다 백업 1명. 백업은 그 파트 PR 리뷰어가 된다 → 컨텍스트가 자연스럽게 2명에게 남는다.
- 5명이면 "관측·장애 대응"을 "플랫폼"과 합치고, 6명이면 그대로.
- 시간이 가장 많은 사람이 통합(파트 사이 붙이기)을 맡는다 — Jeong이 자연스럽게 여기에 들어간다.

### 4.3 Jeong이 가져가면 좋은 조합 【추정】

- 1순위: **리드·설계 문서·일정 + 컨트롤 플레인 API**. 둘 다 "전 영역을 봐야 하는" 자리라 리드 역할이 따라온다.
- 인프라 한 조각은 **배포 파이프라인(CI/CD + Argo)**. 이번 달 실습한 것(Argo CD·Rollouts, kind, k3s)과 겹친다.
- 팀에 k8s 3점이 있으면 플랫폼은 그 사람에게 주고 Jeong은 백업으로 붙어서 배운다. 없으면 플랫폼은 Jeong + Claude PoC 재사용.

안녕하세요, 이정입니다. 인천대 컴공 3학년이고, 인턴 때 프론트, 백엔드, 인프라, PM을 한 번씩 다 돌아봤습니다.

시험이 끝나서 본선까지는 거의 풀타임으로 낼 수 있고, 다만 6일 금요일 저녁 6시부터 10시만 다른 행사 사회가 있어서 그 시간은 빕니다.
맡고 싶은 건 설계 문서랑 API 쪽, 그리고 인프라 한 조각을 붙잡고 배우는 거예요. 회의록이랑 노션 정리는 제가 맡을게요.

## 핵심 결정 3개 (+대안)

1. **1차 회의는 사람·시간·과제만, 설계는 2차** — 대안: 킥오프 밤에 스택·아키텍처까지. 버린 이유: 번복 위험과 Jeong의 준비 시간 부족. 비교표가 설계 문서 재료가 되는 이점도 잃는다.
2. **전원 아키텍처 초안 과제** — 대안: 인프라 잘하는 한 명이 초안. 버린 이유: 한 명 안에 머물면 대안이 안 생기고, 팀 개발 20점의 "대안 문서화"가 빈다.
3. **리드는 주장하지 않고 회의록·노션·통합을 먼저 맡는다** — 대안: 자기소개에서 리드 희망 명시. 버린 이유: 내정자 조언 【추정】대로 강제 리더십은 보이고, 기여로 얻은 영향력만 남는다.
